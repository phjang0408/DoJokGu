# 학교 로비·맵 정리·환경 연출 설계

2026-10-08 작성. 상태: **1~2절 승인. 3~5절은 2026-10-08 검토를 반영했고, 4절 맵 정리 방식은 승인됨.** Blender 새 배치를 Unreal로 옮기고 충돌·지형 재질까지 적용했다(4.2절). PIE 보행 확인이 다음 단계다.

## 1. 목표와 결정 사항

게임을 켜면 메인 메뉴 대신 학교 운동장(CampusEnclosed)에서 시작한다. 플레이어는 캐릭터로 학교 안을 돌아다니며 코트에서 경기를, 학생회관에서 환경설정을 연다.

| 항목 | 결정 |
| --- | --- |
| 로비 형태 | 혼자 돌아다니는 로비(Standalone). 다른 플레이어는 보이지 않는다. AI 학생들이 돌아다녀 학교가 비어 보이지 않게 한다 |
| 경기 연결 | 코트에서 방을 만들면 학교 경기 맵을 Listen Server로 연다. 참가자는 그 서버에 접속한다. 경기가 끝나면 로비로 돌아온다 |
| 방 찾기 | 같은 와이파이(LAN) 방 목록을 자동 검색해 터치로 참가. 기존 IP 주소 참가는 개발용으로 남긴다. 인터넷 대전(EOS)은 이번 범위 밖 |
| 환경설정 | 학생회관 쪽. 소리 볼륨(전체·효과음·배경음), 그래픽 품질(낮음·중간·높음) |
| 메뉴 열기 | 두 방법 모두: 구역에 들어가면 뜨는 버튼 + 화면 구석의 바로가기 버튼(걸어가지 않아도 열림) |
| 캐릭터 선택 | 경기 맵의 대기 단계에서 5명 중 선택하고 준비. 두 사람이 모두 준비하면 첫 서브 |
| 이동 범위 | 학교 담장 안. 밖으로는 나갈 수 없다 |
| 맵 정리 | 의자 방향 수정, 겹친 나무 정리, 빈 곳에 가로등 등 소품 채우기, 크기 조정, 플레이 시야에서 안 보이는 나무·차 등 삭제 |
| 환경 연출 | 도로를 달리는 차, 흐르는 강 |

진행 순서: **맵 정리 → 학교 로비 → 환경 연출.** 로비 구역의 위치는 정리된 배치를 기준으로 잡는다. 환경 연출은 다른 두 작업과 독립적이다.

## 2. 전체 구조 (A안, 승인됨)

학교 배경과 정리된 소품을 Level Instance 하나(`LI_Campus`)로 묶고, 얇은 맵 두 개가 이를 공유한다.

| 맵 | 내용 | 실행 형태 |
| --- | --- | --- |
| `L_Campus_Lobby` | `LI_Campus` + 로비 GameMode, AI 학생, 상호작용 구역, 이동 경계, 로비 HUD | Standalone. 프로젝트 기본 시작 맵 |
| `L_Campus_Match` | `LI_Campus` + `BP_JGCourt`, 관중·심판·치어리더, 경기 GameMode | `?listen`으로 호스트, 참가자는 접속 |

```
앱 시작 → L_Campus_Lobby
   ├─ 학교 산책 (3인칭 카메라, 왼손 조이스틱, 담장 안에서만 이동)
   ├─ AI 학생 배회
   ├─ [코트 구역 / 바로가기] → 경기 패널: 방 만들기 | 방 목록(LAN) → 참가
   │      └─ 방 만들기 = L_Campus_Match?listen 열기
   └─ [학생회관 구역 / 바로가기] → 설정 패널: 볼륨, 그래픽 품질
L_Campus_Match
   ├─ 대기 단계(신규): 캐릭터 선택 + 준비
   ├─ 기존 경기 흐름 (서브 → 득점 → 7점·듀스 → 재경기)
   └─ 나가기 / 호스트 종료 / 접속 끊김 → L_Campus_Lobby
```

- 배경을 한 곳에서만 고치면 두 맵에 함께 반영된다. 로비 전용 액터는 경기 맵에 들어가지 않는다.
- 기존 `L_CampusEnclosed`(10/8 생성)는 `L_Campus_Match`의 출발점으로 쓰고, 배경 액터를 `LI_Campus`로 옮긴다.
- 경기 카메라·판정·코트 크기는 바꾸지 않는다.
- 비용은 로딩 화면 두 번(로비→경기, 경기→로비)이다.

검토한 다른 안: (B) 맵 하나를 URL 옵션으로 모드 전환하는 안은 모드 분기가 곳곳에 퍼져 제외했다. (C) 다시 불러오지 않는 즉석 전환은 Listen Server 구조에서 혼자 하던 세션을 실행 중에 호스트로 바꾸기 어려워 제외했다.

| `AJGInteractZone` | 박스 구역 + 종류(경기·설정). 들어가면 HUD에 버튼 표시, 나가면 숨김 | 코트 앞, 학생회관 입구에 배치 |
| `UJGLobbyHUDWidget` | 조이스틱, 구역 버튼, 구석 바로가기 2개, 경기 패널, 설정 패널 | 기존 `JGVirtualJoystickWidget` 재사용 |
| 경기 패널 | 방 만들기, 방 목록(검색 중·없음·목록 상태), 새로고침, 참가 | 현재 `JGSessionSubsystem`은 세션 없이 `?listen`/주소 접속만 한다. 호스트도 LAN 세션을 만들어야 목록에 보인다. OnlineSubsystem·OnlineSubsystemNull 플러그인과 Build.cs 의존성 추가, Android 실기기 UDP 브로드캐스트 확인 |
| 설정 패널 | 볼륨 슬라이더 3개, 품질 3단계 | `GameUserSettings`의 Scalability와 SoundMix 사용, 저장해서 다음 실행에도 유지. SoundClass(전체·효과음·배경음)와 SoundMix 에셋을 새로 만든다 |
| 이동 경계 | 담장 선을 따라 Pawn만 막는 보이지 않는 벽 | 정문은 닫힌 것으로 처리. 걷는 바닥과 건물 충돌은 4절 맵 정리에서 넣는다 |
| `AJGStudentAI` | 정해진 지점들 사이를 걷다가 잠시 멈추고 감정표현 재생. 6~8명으로 시작 | NavMesh 필요. 외형은 관중용 05·07·08·09·10 재사용. 한 명당 4.4만~6.7만 삼각형이라 모바일 실측 후 늘린다 |

경기 맵에 추가할 것:
- 대기 단계: 기존 `EJGMatchPhase::WaitingPlayers`와 이미 복제되는 `AJGPlayerState::CharacterId`·`bReady`를 사용한다. 새 단계는 만들지 않고 선택·준비 UI와 서버 로스터 검증, 두 사람 준비 시 시작 조건만 추가
- 결과 화면에 "로비로" 버튼, 접속이 끊기면 로비로 이동하고 사유 표시

## 4. 맵 정리 (승인됨)

**방식.** 빌드 스크립트가 맵을 매번 지우고 다시 만들기 때문에 에디터에서 손으로 고친 내용은 남지 않는다. 그래서 모든 정리를 다시 실행할 수 있는 단계로 만든다.

1. `build_campus_level.py`: 지금처럼 GLB 가져오기, 코트 맞춤, 관중 배치
2. `cleanup_campus_level.py`(신규): 빌드 직후 편집 목록 JSON을 적용(삭제·이동·회전·크기·소품 추가·충돌)하고 보고서를 남긴다
3. 이후 로비 단계에서 정리된 배경을 `LI_Campus`로 옮긴다

스크립트와 편집 목록은 git이 추적하는 `Tools/Campus/`에 둔다(`Art/`, `Content/`는 git 제외). 기존 빌드 스크립트도 이곳으로 옮기고 원본 GLB 경로는 그대로 `Art/`를 읽는다. 액터는 가져올 때의 라벨(GLB 노드 이름의 `.`을 `_`로 바꾼 것)로 찾는다.

| 작업 | 방법 |
| --- | --- |
| 안 보이는 것 삭제 | 배경 충돌이 없어 Unreal에서는 광선 검사를 할 수 없으므로 Blender 원본에서 BVH 광선 검사로 계산한다. 검사 지점은 담장 안 보행 영역 격자(눈높이 1.7m)와 양 팀 경기 카메라 위치. 한 번도 맞지 않은 객체 이름을 삭제 목록 JSON으로 내보낸다. 외곽 숲·산은 맵 끝을 가리는 역할이므로 담장 안에서 보이는 것은 남긴다 |
| 겹친 나무 | 줄기 간 수평 거리 2.5m 미만이면 하나를 지운다. 대상과 결과를 보고서에 남긴다 |
| 의자 방향 | 벤치 11개·관람석 2개를 목록으로 보고 코트나 보도를 향하도록 하나씩 회전값을 정한다 |
| 크기 | 소품(벤치·문·차량·가로등·화분)만 캐릭터 키(176~193cm) 기준으로 확인하고 조정한다. 코트 선·네트·건물은 바꾸지 않는다 |
| 빈 공간 | 넓은 보도·광장에 가로등, 벤치, 화분, 휴지통을 놓는다. 위치는 편집 목록에 좌표로 적는다 |
| 충돌 | 지면·포장·경사로·계단은 걷는 바닥 충돌, 건물·나무·담장은 단순 충돌. Pawn만 막고 공 채널은 Ignore 유지. 로비 NavMesh 준비 |
| 성능 | 전체 삼각형 수를 정리 전후로 기록한다. 주요 비중: 아파트 16동 117만, 고폴리 나무 17그루 68만, 숲 2,137그루 70만, 화단 58개 32만(전체 391만). 인스턴스 합치기는 드로우콜만 줄이므로 LOD·HLOD는 모바일 작업에서 다룬다 |

### 4.2 새 배치 이전 (2026-10-08 오후)

Blender에서 길 모듈, 놀이터, 축제 부스, 대문, 자판기·음수대를 추가한 뒤(16:00 저장본) 다음을 진행했다.

1. 백업: `DJG_CampusEnclosed_before_export_1008.blend`, 9/16 GLB, 기존 Unreal 맵·배경 에셋(세션 임시 폴더)
2. `ENC_Archive_PreModular`의 예전 포장·줄눈·도로 표시 3개를 `hide_render`로 내보내기에서 제외
3. 명령줄로 export. Scripting 탭의 Run Script로 실행하면 `__file__`이 `<blend>\<텍스트 이름>`이 되어 출력 위치가 잘못 잡힌다(직접 확인). 새 GLB는 물체 1,981개, 삼각형 317만(이전 391만), 이름 중복 없음. export 스크립트는 GLB와 레이아웃 FBX를 만든 뒤 낱개 모듈 FBX 단계에서 "Module names must be unique"로 멈췄다(차양·담장·투광등 등 같은 이름의 메시 2종). 그래서 `export_validation.json`·`asset_manifest.json`은 갱신되지 않았고, 끝의 `.blend` 재저장도 하지 않았다. Unreal 이전에는 영향 없음
4. 분석: 안 보이는 물체 53개(삼각형 0.8%), 2.5m 미만 나무 쌍 5개. 아직 삭제하지 않음
5. 예전 `L_CampusEnclosed`와 `/Game/Jokgu/Environment/CampusEnclosed`를 지우고 `build_campus_level.py`만 실행(정리 편집 미적용). `success: true`, 배경 1,982개, 에셋 619개. 코트 선·네트는 Blender에서 이미 판정 크기(12×8m, 네트 9m·105cm)
6. 에디터에서 확인: 길 조각 478, 축제 16, 대문 3, 예전 포장 0. 화면상 배치 정상. 지형이 흰색인 것은 Vertex Color 미연결(기존 남은 작업)
7. `campus_edits.json` 갱신: 예전 배치용 delete·transform·add를 비우고 충돌에 새 시설 이름 추가(바닥 22종·막는 물체 44종, 모두 새 GLB 라벨과 일치 확인)

8. export 스크립트의 모듈 이름 중복 수정: 같은 이름의 메시가 둘 이상이면 모듈 FBX를 `_V2`, `_V3`…로 따로 쓴다(원본 백업 `export_campus_enclosed.py.bak_1008`). 다시 export해 `EXPORT_COMPLETE`, 보고서·manifest 갱신. GLB 물체 이름·위치·메시는 이전과 동일해 Unreal 재빌드 불필요
9. 지형 정점 색: 가져온 재질은 GLB 정점 색을 쓰지 않는다. 정리 스크립트의 `materials` 항목이 `/Game/Jokgu/Environment/Materials/M_JG_TerrainVertexColor`(VertexColor → Base Color, 거칠기 0.95, **Nanite 사용 플래그 켬**)를 만들고 지형에 지정한다. 배경 메시가 Nanite라 이 플래그가 없으면 쿡 빌드에서 기본 재질로 그려진다. 화면에서 초록 그라데이션 확인
10. 충돌 적용: `cleanup_campus_level.py` 실행 결과 걷는 바닥 500, 담장 안 막는 물체 159, 메시 349종. 위에서 쏜 검사선이 네트·그네 틀·부스 지붕·체육관 지붕·바닥에 맞음. 공 채널의 Python 이름은 `ECC_JG_BALL`

다음: PIE로 걸어 보며 바닥 빠짐·통과·경계석 걸림 확인 → 벤치 방향·소품 등 개별 편집은 새 배치를 보고 다시 정한다(가능하면 Blender에서).

| 소품 추가 | 남쪽 보도 가로등 5·벤치 2, 본관 뒤 북쪽 보도 가로등 4 |
| 충돌 | 바닥 계열은 걷는 바닥, 담장 안 건물·담장·소품은 막는 물체(Complex-as-Simple). 공·카메라 채널 Ignore. 나무는 충돌 없음 |

**멈춘 이유와 다음 순서.** 배치 원본인 Blender에서 소품 추가와 재배치를 먼저 한다. export 스크립트(`Art/Schoolyard/Scripts/export_campus_enclosed.py`)는 객체를 에셋 이름으로 새로 만들어 Blender가 `.020` 같은 번호를 순서대로 붙인다. 그래서 Blender에서 물체를 추가·삭제하면 번호가 밀린다. 번호가 밀린 상태로 라벨 기준 편집을 적용하면 경고 없이 다른 물체를 회전하거나 지운다. 또 지금 `.blend`는 GLB를 export한 뒤(10/6)에도 수정되어 있어 GLB와 내용이 다르다. Blender 작업이 끝나면 다음 순서로 진행한다.

1. Blender에서 배치 수정. 벤치 방향, 소품 크기, 소품 추가처럼 배치에 속한 수정은 가능하면 여기서 한다. 그러면 다시 export해도 남는다
2. GLB 다시 export
3. `analyze_campus.py`를 다시 실행해 안 보이는 물체·겹친 나무 목록을 갱신하고, 벤치 방향·크기·빈 공간을 새 배치로 다시 확인한다
4. `campus_edits.json` 갱신. Unreal에만 남는 개별 편집이 있으면 정리 스크립트가 라벨 대신 "메시 종류 + 위치(오차 30cm)"로 찾게 바꾸고, 맞지 않으면 실패로 멈추게 한다
5. 에디터를 닫고 `rebuild_campus.py` 실행 → 에디터를 다시 열어 MCP로 삭제 수, 바닥 충돌(trace), 화면 확인

## 5. 환경 연출 (검토 반영)

| 항목 | 방법 |
| --- | --- |
| 달리는 차 | 학교 둘레 도로(폭 8m)에 방향별 Spline 경로 2개를 두고, 기존 차량 메시로 만든 별도 액터가 일정 속도로 반복 주행. 주차된 차는 그대로 둔다. 차 사이 간격 유지. 충돌 없음 |
| 흐르는 강 | 새 재질 `M_JG_River`(시간에 따라 움직이는 UV와 노멀 물결)를 만들어 정리 스크립트에서 강 메시에 지정한다. 가져온 재질 인스턴스는 다시 빌드하면 덮어써지므로 고치지 않는다. 강 UV 방향이 흐름과 맞지 않으면 월드 좌표 기준 패닝을 쓴다. 메시는 그대로 사용 |

두 연출 모두 각 기기에서 따로 재생하며, 네트워크로 동기화하지 않는다.
