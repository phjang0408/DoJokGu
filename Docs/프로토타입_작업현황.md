# 첫 멀티플레이 프로토타입 준비 작업 현황

「족구하세요 개발 준비 계획서」의 1~3단계(코트와 이동, 공과 공격, 첫 멀티플레이 경기)를 **에셋 없이 돌아가는 상태**로 만들어 둔 기록이다. 메시·애니메이션·UI 그림은 나중에 채워 넣고, 판정·상태·네트워크 요청은 C++에 둔다.

## 2. 구현한 경기 규칙 (계획서 2절 결정 사항)

| 항목 | 현재 구현 |
| --- | --- |
| 승리/듀스 | 7점 이상 + 2점 차 (`TargetScore`, `WinMargin`) |
| 첫 서브 | Host가 무작위로 정해 GameState로 복제. 이후 득점자가 서브 |
| 서브 준비 | 1.5초 대기 → 서브 입력 허용, 10초 초과 시 상대 득점(`ServeTimeout`) |
| 서브 위치 | 자기 코트 네트에서 500cm 지점. 점수마다 위치·공·입력 저장·슬라이딩 상태 초기화 |
| 바운드 전 타격 | 허용. 받는 쪽 바운드는 최대 1회 |
| 자기 공 연속 타격 | 금지 (`CanTeamHit`: 기대 수신 팀만 칠 수 있음) |
| 라인 위 착지 | 인. 판정 사각형은 라인 바깥쪽 경계, 코트 선 메시는 경계 안쪽에 그린다 |
| 첫 착지 아웃 / 자기편 착지 | 친 사람 실점 (`OutOnFirstLanding`, `FailedToCross`) |
| 인 바운드 후 재접촉 | 위치 무관 받는 사람 실점 (`NotReturned`) |
| 네트 | 공은 네트에 튕기기만 한다. 넘어가지 못하고 자기편에 떨어지거나 멈추면 친 사람 실점 |
| 이동 영역 | 자기 코트 + 바깥 100cm. Pawn만 막는 보이지 않는 벽(공은 통과) |
| 정지 중 슬라이딩 | 마지막 유효 이동 방향, 없으면 상대 코트 방향 |
| 경기 중 이탈 | 경기 종료 + 남은 사람에게 "Opponent left" 표시. 새 플레이어가 오면 새 경기 |
| 득점 중복 방지 | 라운드당 `bPointResolvedThisRound` 1회 + 득점 후 공 랠리 상태 해제 |

## 3. 핵심 설계

- **Host 권한**: GameMode(서버)가 판정 → GameState의 `FJGMatchSnapshot` 하나로 복제 → Host는 직접, Client는 RepNotify로 같은 `OnMatchStateChanged` 호출 → HUD는 한 경로로 갱신.
- **공**: Sphere 루트 + ProjectileMovement (물리 시뮬레이션 없음). `JGBall` 전용 충돌 채널(기본 Ignore)이라 코트 바닥·네트만 공을 튕긴다. 캐릭터 몸과 충돌하지 않는다. 바닥은 `JGGround` 태그가 붙은 단일 박스라 중복 바운드가 없다.
- **타격**: 클라이언트는 손을 뗄 때 `FJGAttackInput`(종류·각도·파워)을 Server RPC로 한 번 보낸다. 서버는 150ms 입력 저장 슬롯에 넣고 매 틱 거리·높이·수신 차례를 검사해 한 번만 새 속도를 준다. AnimNotify는 판정에 쓰지 않는다.
- **궤적**: 드래그는 파워에 따라 수평/수직 속도를 Curve로 연속 보간 (코트 안 보정 없음). 탭은 네트 위 여유 높이를 지나 네트 뒤 150cm에 떨어지는 포물선을 해석적으로 푼다. 슬라이딩 성공은 높고 느린 반환(1.6초 비행).
- **모션 구간**: 약(<33%)/중/강(≥67%)은 몽타주 선택에만 쓰고 속도는 끊기지 않는다.
- **슬라이딩**: Ready → Sliding(0.35초, RootMotionSource로 CharacterMovement 경유, 리치 확장) → Recovery(0.6초) → Ready.
- **카메라**: 코트가 팀별 카메라 위치를 계산 (약 -60도, 각자 자기 코트가 화면 아래). 좌우 추적은 데드존·비율·최대치로 제한.
- **공 표시**: 공 아래 지면 투영 그림자(높이에 따라 크기 변화)만 표시. 미래 낙하지점은 `jg.Debug.Draw 1`에서만 보인다.

## 4. 조작

| 입력 | PC | 모바일 |
| --- | --- | --- |
| 이동 | WASD / 방향키 / 게임패드 왼스틱 | 왼쪽 아래 조이스틱 |
| 탭 공격 | 화면 오른쪽 절반 마우스 짧게 클릭, 또는 `J` | 오른쪽 절반 짧게 터치 |
| 드래그 공격 | 오른쪽 절반을 마우스로 끌었다 놓기, 또는 `K`(정면 50%) | 오른쪽 절반 드래그 후 놓기 |
| 슬라이딩 | `Space` | (버튼 미구현 → 아래 남은 작업) |
| 재경기 | `R` 또는 결과 화면 Rematch 버튼 | Rematch 버튼 |

드래그 중에는 캐릭터 발밑에 임시 디버그 화살표(초록/노랑/빨강 = 약/중/강)가 그려진다.

## 5. 테스트 방법

1. **규칙 자동 테스트**: Session Frontend > Automation에서 `Jokgu` 필터 실행.
2. **두 명 경기 (PIE)**: `L_TestCourt` 열기 → Play 옵션에서 Number of Players = 2, Net Mode = Play As Listen Server → 실행. 서브 → 랠리 → 득점 → 듀스 → 재경기 흐름 확인.
3. **혼자 경기 흐름**: `BP_JGGameMode`의 `bAllowSoloMatch`를 켜고 1인 PIE.
4. **공 궤적 단독 테스트**: 월드 세팅 GameMode Override를 `BP_JGGameMode_Practice`로 바꾸면 `BP_JGBallLauncher`가 약/중/강/최대/탭을 3초마다 발사하고, 착지 판정이 화면에 표시된다. 콘솔 `jg.Debug.Draw 1`로 코트 영역·리치·예상 궤적 확인.
5. **수치 조정**: `Content/Jokgu/Data/DA_Balance_Default` 한 곳에서만 수정한다 (Project Settings > Game > Jokgu에 지정됨).

## 7. 캐릭터 리그 연결 (DJG 공통 리그)

원본과 제작 스크립트는 `Art/Characters/Rigged` (계획 `PLAN_KO.md`, 검증 `Reports/`). Unreal 결과물은 `Content/Jokgu/Characters/Rigged`.

| 항목 | 내용 |
| --- | --- |
| 메시 | `Meshes/SK_DJG_01~12_*` 12종, 공통 스켈레톤 `SK_DJG_Common_Skeleton`(26뼈), 키 176~193cm, 정면 +X |
| 재질 | `Materials/M_DJG_Palette` 하나(팔레트 텍스처 + 러프니스), SkeletalMesh 사용 플래그 켬 |
| 애니메이션 | `Animations/A_DJG_*` 18종, 30fps, 제자리 동작(루트 모션 없음) |
| 몽타주 | `Montages/AM_DJG_*` 12종. Tap/Weak/Medium/Strong/Serve에 `Contact` 섹션 (0.20 / 0.30 / 0.37 / 0.53 / 0.63초) |
| 데이터 | `Data/DA_DJG_01~12_*` (메시·AnimClass·몽타주 지정, 능력치 기본 3) |
| 게임 연결 | `BP_JGCharacter` 메시 = 01_Captain, `JGAnimInstance`, 위치 Z -96, 회전 0. `DA_Char_KimDoyun`에 같은 메시와 몽타주 지정 (GDD 능력치 유지) |

- 서버가 공을 먼저 발사하고 멀티캐스트로 몽타주를 재생하므로 킥·서브는 `Contact` 섹션부터 재생한다. 슬라이딩만 처음부터 끝까지 재생한다.
- 대기/걷기/달리기는 `JGAnimInstance`가 속도(걷기 180, 달리기 450)로 블렌드한다. AnimBP 에셋은 없다.
- 다시 가져오기: 에디터를 닫고 `UnrealEditor-Cmd.exe DoJokgu.uproject -run=pythonscript -script=<프로젝트>/Art/Characters/Rigged/Unreal/import_rigged_characters.py -EnablePlugins=PythonScriptPlugin,EditorScriptingUtilities -unattended -nullrhi -DDC-ForceMemoryCache`. 결과는 `Reports/unreal_import_report.json`.
- 12종은 외형 자산이다. GDD의 5인(김도윤 등)에 어떤 외형을 쓸지는 아직 정하지 않았고 `CharacterRoster`에도 추가하지 않았다.
- 확인한 것: 2인 PIE에서 양쪽 캐릭터가 네트를 향하고 팔레트 재질로 보임, `Jokgu.*` 테스트 4개 통과. 킥·슬라이딩 몽타주와 이동 블렌드는 직접 조작해 확인해야 한다.

## 8. 남은 작업 (코드)

- 모바일 슬라이딩 버튼 위젯 (현재 PC `Space`만)
- 서버 측 이동 제한 검증 (지금은 서브 중 이동 금지를 클라이언트에서만 막음)
- Client 공 표시 보간 (8절 2~3단계) — 현재는 복제 위치 + 클라이언트 외삽
- 네트 평면 통과 시점 기록 (현재는 네트 충돌체 + 착지 위치로 판정)
- 로비(캐릭터 선택·Ready), 메인 메뉴 맵, EOS 세션 교체
- Android 패키징·실기기 확인, 모바일 렌더링 설정 검증
